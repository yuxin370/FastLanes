# Rebuild inference references and H2D inputs

Contracts, sample selections and prediction arrays are generated by the benchmark
drivers. They are not pretrained models and do not need to be downloaded from the
original experiment machine. This guide builds new references from public model
code, published checkpoints and ImageNet, then profiles those new runs.

Run commands from the FastLens repository root in the environment described in
the [build instructions](../../../README.md) and
[benchmark setup](../README.md). Use the default `build/` directory for the
commands below. Keep new measurements separate from the published tables in
`benchmarks/paper/results/`.

## Public inputs

| Input | Source and local destination |
| --- | --- |
| ImageNet-1K validation images | Obtain the 50,000-image validation set and labels from [ILSVRC2012](https://www.image-net.org/challenges/LSVRC/2012/). Access requires registration; the dataset is not redistributed here. |
| ViT-Ti and SwinV2-T models | [RGB-no-more](https://github.com/JeongsooP/RGB-no-more), including its `dct_manip` extension, public index CSVs and RGB/DCT checkpoints. |
| DCT ResNet-50 and MobileNetV2 | [DCTNet classification code](https://github.com/kaix-nv/DCTNet/tree/master/classification) and the pretrained model folders linked from its README. |
| eFUN | [FUN](https://github.com/kfirgoldberg/FUN); use the source revision and checkpoint instructions in [EFUN.md](../dct_models/EFUN.md). |
| H2D profiling | NVIDIA Nsight Systems (`nsys`) with CUDA tracing enabled. |

Set up RGB-no-more and compile `dct_manip` using its upstream installation
instructions. Its extension paths must point to the libjpeg installation in your
environment. Use the same Python environment for FastLens and the benchmark.

```bash
export RGBNOMORE_ROOT="$HOME/RGB-no-more"
git clone https://github.com/JeongsooP/RGB-no-more.git "$RGBNOMORE_ROOT"
export PYTHONPATH="$PWD:$PWD/build/fastlens/torch${PYTHONPATH:+:$PYTHONPATH}"
export FASTLENS_DATA="$PWD/fastlens/data"
export FASTLENS_RUNS="$PWD/results/rebuilt"
mkdir -p "$FASTLENS_DATA/system_rgbnomore/e2e_v2/checkpoints" "$FASTLENS_RUNS"
cp "$RGBNOMORE_ROOT/assets/indexbase_val.csv" \
  "$FASTLENS_DATA/system_rgbnomore/e2e_v2/indexbase_val.csv"

for name in imgnetRGBViTTi_ep300_74.1.pth imgnetDCTViTTi_ep300_75.1.pth \
            imgnetSwinRGB_ep300_79.0.pth imgnetSwinDCT_ep300_79.4.pth; do
  curl --fail --location \
    "http://www-personal.umich.edu/~jespark/rgbnomore-2023/$name" \
    --output "$FASTLENS_DATA/system_rgbnomore/e2e_v2/checkpoints/$name"
done
```

These are the checkpoint filenames published by RGB-no-more. For DCTNet, clone
the official source into the ignored dependency location:

```bash
git clone https://github.com/kaix-nv/DCTNet.git fastlens/benchmarks/dct_models/DCTNet
```

Download the DCTNet checkpoints from its upstream model links and extract them
under `fastlens/data/system_rgbnomore/e2e_v2/checkpoints/` as follows:

```text
resnet50dct_upscaled_static_24/model_best.pth.tar
resnet50dct_upscaled_static_64/model_best.pth.tar
mobilenetv2dct_upscaled_static_24/model_best.pth.tar
mobilenetv2dct_upscaled_static_32/model_best.pth.tar
efun.pth
```

Install the DCTNet preprocessing dependencies (`opencv-python`, `jpeg2dct`,
`PyTurboJPEG` and libjpeg-turbo) as described upstream. Its adapter loads
`libturbojpeg.so` from the active Python environment's `lib/` directory. The
eFUN adapter uses the author's bundled timm fork in a separate process.

## Prepare the validation source

The common source is a 512×512 RGB JPEG encoded with Pillow, bilinear resize,
quality 75 and 4:2:0 subsampling. Model-specific crop, resize and normalization
remain online. The following preparation uses the public RGB-no-more CSV to
preserve filenames and checkpoint label identities.

Set `IMAGENET_VAL` to the extracted, original validation images. They may be in
one directory or organized into class directories; original validation filename
stems must be preserved. Run this once into a fresh destination:

```bash
export IMAGENET_VAL=/path/to/ILSVRC2012/val
python - <<'PY'
import csv
import os
from concurrent.futures import ThreadPoolExecutor
from pathlib import Path
from PIL import Image

original = Path(os.environ['IMAGENET_VAL'])
source = Path(os.environ['FASTLENS_DATA']) / 'system_rgbnomore/e2e_v3/imagenet_512'
index = Path(os.environ['RGBNOMORE_ROOT']) / 'assets/indexbase_val.csv'
with index.open() as stream:
    rows = list(csv.DictReader(stream))
inputs = {p.stem: p for p in original.rglob('*')
          if p.suffix.lower() in {'.jpg', '.jpeg', '.jpe'}}
assert len(rows) == len(inputs) == 50000
(source / 'val').mkdir(parents=True, exist_ok=False)

def convert(row):
    relative = Path(row['Filepath'].removeprefix('./'))
    target = source / relative
    target.parent.mkdir(parents=True, exist_ok=True)
    with Image.open(inputs[relative.stem]) as image:
        image.convert('RGB').resize((512, 512), Image.Resampling.BILINEAR).save(
            target, format='JPEG', quality=75, subsampling=2)

with ThreadPoolExecutor(max_workers=len(os.sched_getaffinity(0))) as pool:
    list(pool.map(convert, rows))
PY

python -m fastlens.benchmarks.baselines.system_rgbnomore.dataset.prepare_dataset \
  --split val \
  --data-root "$FASTLENS_DATA/system_rgbnomore/e2e_v3/imagenet_512" \
  --out-dir "$FASTLENS_DATA/compressed/imagenet512_val_compact_v3" \
  --index-file "$RGBNOMORE_ROOT/assets/indexbase_val.csv" \
  --expected-image-size 512 --expected-image-count 50000
```

This writes `manifest.bin`, `labels.json` and reconstructable quantization
metadata. The preparation driver checks the image population and metadata.
Next create the full validation selection consumed by the CNN evaluators. It
uses the same sorted-path physical IDs as the converter:

```bash
python - <<'PY'
import json
import os
from pathlib import Path
from fastlens.benchmarks.baselines.system_rgbnomore.training.generate_imagenet_manifests import (
    MANIFEST_FORMAT, LABEL_MAPPING, _build_samples, _collect_jpegs, _load_labels)

data = Path(os.environ['FASTLENS_DATA'])
root = data / 'system_rgbnomore/e2e_v3/imagenet_512/val'
paths = _collect_jpegs(root)
labels = _load_labels(Path(os.environ['RGBNOMORE_ROOT']) / 'assets/indexbase_val.csv')
assert len(paths) == len(labels) == 50000
samples = _build_samples(range(len(paths)), paths=paths, labels=labels,
    jpeg_root=root, source_split='val', sampling={i: '4:2:0' for i in range(len(paths))},
    probe_dimensions=False, progress_interval=10000)
destination = data / 'system_rgbnomore/e2e_v3/training_manifests_official_v3/val.json'
destination.parent.mkdir(parents=True, exist_ok=True)
with destination.open('x') as stream:
    json.dump(dict(format=MANIFEST_FORMAT, split='val', source_split='val',
        label_mapping=LABEL_MAPPING, validation_semantics='official-imagenet-validation',
        samples=samples), stream, indent=2)
PY
```

The `galp_image_id` key and versioned on-disk identifiers are retained by the
existing data format. They identify physical image positions, not another
source repository or an additional dependency.

## Generate full inference references

The ViT/Swin inference driver constructs its own contract and sample manifest.
It records the current checkpoints, native binary and source files; it also
writes per-sample predictions and executes the semantic validator.

```bash
python -m fastlens.benchmarks.baselines.system_rgbnomore.inference.run \
  --preset smoke --model rgbnomore-vitti-224-v1 \
  --pipelines rgbnomore pytorch dali \
  --batch-size 50 --warmup-batches 0 --measurement-batches 1000 \
  --semantic-samples 8 --repeats 1 --workers 8 \
  --output-dir "$FASTLENS_RUNS/vitti_reference"

python -m fastlens.benchmarks.baselines.system_rgbnomore.inference.run \
  --preset smoke --model rgbnomore-swinv2-t-256-window8-v1 \
  --pipelines rgbnomore pytorch dali \
  --batch-size 50 --warmup-batches 0 --measurement-batches 1000 \
  --semantic-samples 8 --repeats 1 --workers 8 \
  --output-dir "$FASTLENS_RUNS/swin_reference"
```

The `smoke` preset permits a baseline-only pipeline list; the explicit counts
above override its small defaults to process all 50,000 images. The `e2e` preset
requires all four pipelines, including the image-major FastLens path. Native
block-major references are generated separately below.

Install DALI using the [RGB baseline instructions](../baselines/system_rgbnomore/README.md)
before selecting it. A `--dry-run` creates the contract and command list without
running inference, but still requires the actual source data and checkpoint
files. It does not generate predictions.

Each completed directory contains `contract.json`, `sample_manifest.json`,
`commands.json`, `pipeline_*.json`, semantic prediction arrays and
`validation.json`. Inspect the validator result before using a reference.
The commands above generate one complete 50,000-image pass for correctness and
H2D capture; repeated throughput trials use the chapter's measurement settings.
`--semantic-samples` controls the smaller tensor/logit probe. The driver records
prediction agreement over the full measured population separately.

For the CNN source-DCT route, generate predictions directly from JPEGs:

```bash
for profile in mobilenet24 mobilenet32 resnet24 resnet64; do
  DCTNET_PROFILE="$profile" python -m fastlens.benchmarks.dct_models.evaluate \
    --route J --count 50000 --batch-size 64 --workers 16 --device cuda \
    --output-dir "$FASTLENS_RUNS/$profile/reference"
done
python -m fastlens.benchmarks.dct_models.efun evaluate \
  --route J --count 50000 --batch-size 64 --workers 16 --device cuda \
  --output-dir "$FASTLENS_RUNS/efun/reference"
```

The outputs include `J_50000.json`, `samples_50000.json` and `profile.json`.
Route J performs online source-DCT geometry; route R follows the upstream
pixel-resize/re-encode recipe. Keep those references separate because their
preprocessing semantics differ. For example, the full-inference worker accepts
the newly generated source-DCT reference explicitly:

```bash
python -m fastlens.benchmarks.paper.shared.remaining_baseline_inference \
  --model mobilenet24 --path cpu_dct \
  --reference "$FASTLENS_RUNS/mobilenet24/reference/J_50000.json" \
  --output "$FASTLENS_RUNS/mobilenet24/cpu_dct_check" --check
```

## Prepare native source-DCT inference

The full-frequency block-major representation is built from those same source
JPEGs. With DCTNet installed, the existing source preparation command writes
the shards, verifies their coefficients and builds the access index:

```bash
python -m fastlens.benchmarks.dct_models.prepare_online_source \
  --output-dir "$FASTLENS_DATA/compressed/imagenet512_val_block_major"
```

Before native inference, materialize the GPU access schedule using the
[block-major run guide](../system_dct_major/docs/RUN_GUIDE.md#build-and-prepare-access-metadata).
The compact and block-major stores above share sorted-path image IDs, so they
can use the same `labels.json`. Generate a native ViT reference with all 64
source frequencies:

```bash
python -m fastlens.benchmarks.system_dct_major.run \
  --preset e2e --workload evaluation \
  --pipelines dct_major_pushdown rgbnomore \
  --dct-major-manifest "$FASTLENS_DATA/compressed/imagenet512_val_block_major/manifest.bin" \
  --dct-major-label-map "$FASTLENS_DATA/compressed/imagenet512_val_compact_v3/labels.json" \
  --block-major-access-dir "$FASTLENS_DATA/compressed/imagenet512_val_block_major/access" \
  --dct-coeffs all --sample-count 50000 --batch-size 50 \
  --warmup-batches 0 --measurement-batches 1000 --semantic-samples 32 --repeats 1 \
  --output-dir "$FASTLENS_RUNS/vitti_native"
```

For CNN native crop/projection comparisons, use
[ONLINE_CROP.md](../dct_models/ONLINE_CROP.md). Those evaluators compare predictions
against the JPEG source-DCT route from the same selection. A new run must retain
its own reference and validation outputs; copying predictions from another
preprocessing route would not establish equivalence.

## Capture H2D traffic

Use a command from a newly generated `commands.json`. The example profiles
ViT CPU-DCT inference. Set `run` to `vitti_native` and `pipeline` to
`dct_major_pushdown` to capture the native path. Use a new output directory for
each capture.

```bash
python - <<'PY'
import json
import os
import subprocess
import sys
from pathlib import Path

root = Path.cwd()
run = Path(os.environ['FASTLENS_RUNS']) / 'vitti_reference'
pipeline = 'rgbnomore'
record = next(r for r in json.loads((run / 'commands.json').read_text())
              if r['name'] == pipeline)
destination = run / ('h2d_' + pipeline)
destination.mkdir(exist_ok=False)
command = record['command'][1:]  # The profiler supplies the Python interpreter.
command[command.index('--output') + 1] = str(destination / 'pipeline.json')
command_path = destination / 'workload_command.json'
command_path.write_text(json.dumps(command))
env = dict(os.environ, PYTHONDONTWRITEBYTECODE='1')
env.update(record.get('env_overrides', record.get('env', {})))
profiler = root / 'fastlens/benchmarks/paper/section_6_3/h2d_traffic/profile_section42.py'
subprocess.run(['nsys', 'profile', '--trace=cuda,nvtx', '--sample=none',
    '--cpuctxsw=none', '--capture-range=cudaProfilerApi', '--capture-range-end=stop',
    '--output', str(destination / 'capture'), sys.executable, '-B', str(profiler),
    '--command', str(command_path), '--mode', 'profile', '--output', str(destination)],
    env=env, check=True)
subprocess.run(['nsys', 'export', '--type', 'sqlite',
    '--output', str(destination / 'capture.sqlite'),
    str(destination / 'capture.nsys-rep')], check=True)
from fastlens.benchmarks.paper.section_6_3.h2d_traffic.run_section42_resources import metrics
result = metrics(destination, 'profile', 50000)
(destination / 'h2d.json').write_text(json.dumps(result, indent=2))
print(json.dumps(result, indent=2))
PY
```

The profiler instruments the existing measured-pass boundary. The extractor
counts host-to-device CUPTI copies inside `fastlens.measured_pass` and checks
that copies do not cross that boundary. It reports total bytes, bytes per image
and copy count. Treat these as profiling measurements; collect throughput in a
separate unprofiled run.

The same profiler supports `dct_models/evaluate.py`, `evaluate_rgb.py` and
`evaluate_shards.py`. For CNN captures, write their argument list (starting with
`-m`, followed by the module and arguments) to `workload_command.json`, set the
same `DCTNET_PROFILE`, and use a fresh `--output-dir`. The evaluator's default
warmup runs outside the measured pass. Preserve the sample count when computing
bytes per image.

Training additionally requires the full 1,281,167-image training split and its
prepared manifests. Follow the
[training preparation and execution guide](../baselines/system_rgbnomore/docs/TRAINING_BENCHMARK_RUN_GUIDE.md)
and the [PLS guide](../training_pls/README.md) for the native training layout.
For example, after preparing those training inputs, capture the RGB PyTorch
window on an RTX 4090 as follows. The training driver creates its sample order
and model initialization from the configured seed; an inference prediction
bundle is not an input to this command.

```bash
nsys profile --trace=cuda,nvtx --sample=none --cpuctxsw=none \
  --capture-range=cudaProfilerApi --capture-range-end=stop \
  --output "$FASTLENS_RUNS/training_pytorch_capture" \
  python -m fastlens.benchmarks.paper.shared.training_window_rgb \
    --gpu 4090 --model vitti --pipeline pytorch --trial 0 \
    --measured-images 65536 --profile \
    --output "$FASTLENS_RUNS/training_pytorch"
nsys export --type sqlite \
  --output "$FASTLENS_RUNS/training_pytorch/capture.sqlite" \
  "$FASTLENS_RUNS/training_pytorch_capture.nsys-rep"
python - <<'PY'
import json
import os
from pathlib import Path
from fastlens.benchmarks.paper.section_6_3.h2d_traffic.run_section42_resources import metrics
destination = Path(os.environ['FASTLENS_RUNS']) / 'training_pytorch'
run = json.loads((destination / 'result.json').read_text())
print(json.dumps(metrics(destination, 'profile', run['consumed_samples']), indent=2))
PY
```

The output records the actual consumed sample count. Use it as the denominator
when profiling other supported training windows. For unprofiled training
throughput, first run `--check` and pass its `result.json` through
`--correctness-report`, as required by the training driver.

## Connect fresh references to the chapter entry points

The chapter runners accept `--references FILE`. This JSON configuration maps GPU,
model and pipeline names to files generated on the current installation. Paths
are relative to the configuration file; absolute paths also work. The default is
`results/rebuilt/references.json`. GPU names are `4090` and `H100`; model names are
`vitti`, `swinv2`, `mobilenet24`, `mobilenet32`, `resnet24`, `resnet64` and `efun`.
Pipeline names are `cpu_dct`, `fastlens`, `pytorch`, `dali`, `coordl`, `ffcv_raw`,
`ffcv_jpeg` and `l3`.

Existing evaluator outputs can be used directly. For example:

```json
{
  "4090": {
    "mobilenet24": {
      "cpu_dct": {"reference": "mobilenet24/reference/J_50000.json"},
      "fastlens": {"reference": "mobilenet24/native/N_50000.json"}
    }
  }
}
```

Alternatively, generate the complete matched-DCT reference set with the inference
workers used by the chapters. First finish the public-input and native-store
preparation above. ViT uses `vitti_native/contract.json` from the DCT-major driver;
Swin uses `swin_reference/contract.json` from its model-specific inference driver.
The following creates the input/output configuration for all seven models:

```bash
python - <<'PY'
import json
import os
from pathlib import Path

root = Path(os.environ['FASTLENS_RUNS'])
contracts = {'vitti': 'vitti_native/contract.json',
             'swinv2': 'swin_reference/contract.json'}
models = ('vitti', 'swinv2', 'mobilenet24', 'mobilenet32', 'resnet24', 'resnet64', 'efun')
references = {}
for gpu in ('4090', 'H100'):
    references[gpu] = {}
    for model in models:
        references[gpu][model] = {}
        for pipeline in ('cpu_dct', 'fastlens'):
            entry = {'reference': f'references/{gpu}/{model}/{pipeline}/result.json'}
            if model in contracts:
                entry['contract'] = contracts[model]
            references[gpu][model][pipeline] = entry
with (root / 'references.json').open('x') as stream:
    json.dump(references, stream, indent=2)
PY

python -m fastlens.benchmarks.paper.prepare_references \
  --references "$FASTLENS_RUNS/references.json" --gpus 4090 H100
python -m fastlens.benchmarks.paper.section_6_2_1.matched_dct.run run \
  --references "$FASTLENS_RUNS/references.json" --phases inference
```

Reference preparation runs all 50,000 images and refuses to replace an existing
reference. It is a separate preparation pass, not a measured chapter trial or a
passed comparison against an independent oracle. Dataset conversion verification
and the model-specific semantic checks above remain part of preparation.
Measured chapter runs require references and compare predictions against them;
they never generate a missing reference automatically. Use
`--gpus 4090 --models mobilenet24` on both commands to run one workload first.
`prepare_references --dry-run` validates contract paths and prints commands;
chapter `run --dry-run` prints the experiment matrix without loading inputs.

For deployment inference, add the six RGB pipelines to the relevant models in
the configuration. Use `references/<gpu>/<model>/<pipeline>/result.json` as each
new reference destination. Supply a `contract` for ViT and Swin, and for CNN
CoorDL, FFCV and L3. Contracts must describe the current samples, checkpoints and
reader configuration. Inference drivers write contracts with `--dry-run` too;
this still requires real input files and weights.

Use the DCT-major driver's `--coordl-cache-size` and `--ffcv-beton` options to
configure those readers, after the [FFCV preparation](../baselines/ffcv/README.md).
Keep separate contracts for raw and JPEG FFCV. Swin contracts must retain its
model profile and 256-pixel preprocessing: use its model-specific inference
contract as the base when adding a reader configuration. CNN input-adapter
contracts retain the canonical sample IDs/labels and 224-pixel RGB preprocessing;
the CNN worker supplies its model and ImageNet normalization.

For example, create Swin's FFCV inputs from its own sample manifest, preserving
both the stored ordinals and the model's preprocessing:

```bash
python -m fastlens.benchmarks.system_dct_major.ffcv_dataset \
  --sample-manifest "$FASTLENS_RUNS/swin_reference/sample_manifest.json" \
  --output "$FASTLENS_RUNS/swin_ffcv_raw/val.beton" --workers 8
python -m fastlens.benchmarks.baselines.ffcv.prepare_compressed_ffcv \
  --samples "$FASTLENS_RUNS/swin_reference/sample_manifest.json" \
  --output "$FASTLENS_RUNS/swin_ffcv_jpeg"
python - <<'PY'
import json
import os
from pathlib import Path

root = Path(os.environ['FASTLENS_RUNS'])
for encoding in ('raw', 'jpeg'):
    contract = json.loads((root / 'swin_reference/contract.json').read_text())
    destination = root / f'swin_ffcv_{encoding}'
    contract['pipelines']['ffcv'] = {'beton': str(destination / 'val.beton'),
                                    'shuffle': False}
    with (destination / 'contract.json').open('x') as stream:
        json.dump(contract, stream, indent=2)
PY
```

Use `swin_ffcv_raw/contract.json` and `swin_ffcv_jpeg/contract.json` for the
corresponding reference entries. For ViT and CNN readers, use the same commands
with `vitti_native/sample_manifest.json` and `vitti_native/contract.json` as the
inputs, and distinct output directories. This contract already describes the
physical sample order and 224-pixel crop expected by those workers. Generate
each model's reference separately; predictions are not shared between models.

For L3, set `pipelines.dali.l3.root` and `pipelines.dali.l3.library` in the model's
contract to the converted dataset and decoder from [L3 setup](../baselines/l3/README.md).
After adding new pipelines, prepare their references with a configuration
containing only those new entries, then pass the combined configuration to
`section_6_2_3.deployment.run --references FILE`.

Training entry points accept `--l3-root`, `--l3-library` and `--ffcv-jpeg-root`.
Their defaults are `fastlens/data/baselines/l3`,
`build/baselines/l3/libl3-patch32.so` and `results/preparation/ffcv_jpeg/train`.
Raw FFCV training inputs remain under `results/preparation/p0_ffcv`. Prepare the
JPEG representation with:

```bash
python -m fastlens.benchmarks.baselines.ffcv.prepare_compressed_ffcv \
  --samples results/preparation/p0_ffcv/samples.json --training \
  --output results/preparation/ffcv_jpeg/train
```

## Profile newly completed chapter trials

Chapter runs write `run.command.json` beside each result, including the GPU,
model, pipeline and required environment settings. After completing matched-DCT
and deployment trials, profile those new trials with:

```bash
python -m fastlens.benchmarks.paper.section_6_3.h2d_traffic.run run \
  --run-dir results/reproduced --gpus 4090 --models vitti mobilenet24
```

The runner selects one completed trial per workload and excludes correctness
checks and resident-only controls. It preserves the original command and
training correctness report, then checks the profiled result against the
unprofiled trial's predictions/checkpoint or training state. Memory diagnostics
and profiling remain separate from throughput measurement, using the original
timer boundaries and CUPTI accounting. No archived experiment tree is required.
The default Fig. 14 matrix retains the seven main paths; the separate FFCV-JPEG
diagnostic is not added to those 28 points.

New contracts describe your source files, build and checkpoints. Keep them with
their predictions, sample selections and validation outputs. They reproduce
the evaluation procedure; they are not byte-identical copies of the original
machine's contracts, nor replacements for the published measurement tables.
